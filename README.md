# О!дин запрос — AI-агент поездки (трек «О!дин запрос»)

Пользователь описывает поездку одной фразой, а агент ведёт его до покупки: предлагает направления с погодой, ценой и временем в пути, собирает перелёт или поезд, отель и трансфер в три варианта, объясняет выбор и компромиссы, проверяет состыковки, пересобирает план при изменениях и оформляет (имитированный) заказ.

- Видео-скринкаст: _добавим к сдаче_
- Развёрнутый сервис: _опционально_

## Быстрый старт

```bash
git clone git@github.com:ostrovok-hackathon-2026/iskusstvennyi-praim.git
cd iskusstvennyi-praim
cp .env.example .env   # необязательно: без ключа LLM агент работает на правилах
docker compose up --build
# открыть http://localhost:8080
```

Попробуйте: «Хочу к тёплому морю в ноябре, недорого, с ребёнком, без долгих перелётов» → «давай первый» → «а если на два дня позже?» → «беру 1 вариант» → «да, оформляй» → «запроси ранний заезд».

## Языковая модель и надёжность

Модель необязательна. Без ключа агент понимает реплики по правилам, и весь путь до покупки работает. С ключом модель лучше понимает свободные формулировки. Подключение — в `.env`: любой OpenAI-совместимый провайдер (Cloud.ru, Yandex AI Studio, vLLM, Ollama) или GigaChat с бесплатным тарифом (`LLM_PROVIDER=gigachat`, токен обновляется сам). Проверка ключа: `make llm-check`.

Подключение Cloud.ru за 2 минуты:

```bash
cp .env.example .env
# в .env: LLM_API_KEY=<ключ сервисного аккаунта Cloud.ru>
#         LLM_MODEL=Qwen/Qwen3-235B-A22B-Instruct-2507  (или openai/gpt-oss-120b)
make llm-check      # связь, JSON-режим, задержка и понимание 8 фраз: LLM против правил
make simulate       # LLM играет 8 путешественников
```

Модель только понимает реплику. Её ответ сверяется с текстом и с правилами (`domains/trips/arbiter.py`):

- оформление и отмена — только по явному согласию, которое видят правила; «давай подумаем», «да нет», вопрос — не согласие; отмена брони в два шага;
- поле без опоры в тексте отбрасывается (модель выдумала «с собакой» или повторила «на два дня позже» из прошлой реплики);
- в датах, числах и действиях главнее правила;
- после трёх сбоев подряд модель 30 секунд не вызывается, агент идёт по правилам; отказ провайдера от `response_format` и ответ «в форме схемы» обрабатываются.

## Качество

`make eval` прогоняет 16 сценариев «от фразы до результата» (`eval/scenarios.json`) в трёх режимах и пишет `eval/report.md`:

| Режим | Доведено до цели | Ложных покупок и отмен |
| :--- | ---: | ---: |
| Правила, без LLM | 16/16 | 0 |
| «Плохая модель»: таймауты, мусор, ложное «да», повторы и выдумки | 16/16 | 0 |

Отдельно агент прошёл независимое ревью: ~12 тысяч реплик в 1500 случайных диалогах и 150 ручных (опечатки, разговорные фразы, исправления «не Сочи, а Казань», смена состава, перенос после покупки). Падений нет; найденные ошибки понимания исправлены и закреплены тестами `tests/test_review_cases.py`.

Сценарии написаны командой, поэтому настоящая проверка — `make simulate`: LLM играет 8 путешественников (семья с ребёнком, сомневающаяся пара, хозяин собаки, охотник за скидками и другие) и разговаривает с агентом своими словами. Нужен ключ LLM.

## Зависимости и переменные окружения

Рекомендованные ресурсы: 1 CPU, 512 МБ RAM. Внешних сервисов (БД, кэш) нет: состояние диалогов в памяти процесса, данные лежат в образе.

| Переменная | По умолчанию | Назначение |
| :--- | :--- | :--- |
| `APP_PORT` | `8080` | Порт приложения |
| `LLM_PROVIDER` | `openai` | `openai` — OpenAI-совместимый API, `gigachat` — GigaChat |
| `LLM_API_KEY` | пусто | Ключ OpenAI-совместимой LLM. Пусто — понимание запросов по правилам |
| `GIGACHAT_AUTH_KEY`, `GIGACHAT_SCOPE`, `GIGACHAT_VERIFY_SSL` | пусто, `GIGACHAT_API_PERS`, `1` | Для GigaChat |
| `LLM_BASE_URL` | `https://foundation-models.api.cloud.ru/v1` | Адрес провайдера |
| `LLM_MODEL` | `Qwen/Qwen3-235B-A22B-Instruct-2507` | Модель |
| `LLM_JSON_MODE` | `1` | Передавать `response_format=json_object` |
| `LLM_SCHEMA_MODE` | `0` | Строгая JSON-схема ответа, если провайдер умеет |
| `LLM_TIMEOUT` | `8` | Таймаут запроса к LLM, с |
| `LLM_NLG` | `0` | Перефразировать ответы через LLM (факты не меняются) |

## Данные

Островок не даёт API и данных, поэтому:

- **Погода — реальная.** Средние по месяцам за 2022–2025 годы из [Open-Meteo](https://open-meteo.com) (CC BY 4.0): температура днём и ночью, дождливые дни, температура моря. Файл `domains/trips/data/climate.json` лежит в репозитории, пересобирается командой `python -m tools.build_climate`.
- **Фото направлений — реальные**, из Wikimedia Commons со свободными лицензиями; автор и лицензия подписаны на каждом снимке (`tools/build_images.py`, `apps/static/img/credits.json`). Фото отелей — иллюстрации по типу отеля, так и подписаны.
- **Карта — реальная.** Контуры суши Natural Earth 110m (public domain), превращённые в сетку точек (`tools/build_landdots.py`).
- **Направления — реальные.** 34 направления (15 по России, 19 за рубежом), 7 городов вылета: координаты, аэропорты, визовый режим, сезоны.
- **Отели, рейсы, поезда, трансферы и цены — модельные (синтетика).** Генерируются детерминированно: время в пути считается по реальному расстоянию, цены зависят от сезона, перевозчики вымышленные («Авиа Альфа»). Оплата имитируется.

Сидирование не нужно: всё создаётся при старте.

## Маршруты

- `/` — веб-интерфейс: точечная карта с маршрутом, направления с фотографиями, календарь цен «когда выгоднее ехать», варианты с лентой «поездка по часам», корзина, заказ в виде посадочного талона; чат справа
- `/health` — `{"status": "ok"}`
- `POST /api/chat` — `{"text": "...", "session_id": "..."}` → ответ агента, этап, понятые параметры и данные для карточек
- `GET /api/info`, `POST /api/reset`, `/api/docs` — описание API

Тестовые учётные данные не нужны.

## Как устроено

Управляемый агент: LLM только извлекает из реплики пожелания и действия в Pydantic-схему, а решения принимает код — какой вопрос задать, какие направления предложить, как собрать и сравнить варианты, когда оформлять. Поэтому агент не выдумывает отели и цены, а демо работает и без ключа LLM.

```
реплика → защита от инъекций → понимание (LLM, правила дополняют и страхуют)
        → слияние с состоянием поездки → решение этапа:
          нет направления  → вдохновение: 3 направления с погодой, ценой, дорогой, рисками
          нет дат          → один вопрос (или агент сам выбирает самые выгодные даты месяца)
          всё есть         → 3 варианта: оптимальный / экономный / комфорт + проверка состыковок
          выбор            → корзина → «да» → заказ → ранний заезд, поздний выезд, перенос, отмена
        → изменения («на два дня позже», «дешевле», «с собакой») пересобирают план и показывают, что изменилось
```

| Путь | Назначение |
| :--- | :--- |
| `domains/trips/geo.py` | Направления, города вылета, расстояния |
| `domains/trips/climate.py` | Климат по месяцам (Open-Meteo) |
| `domains/trips/offers.py` | Модельные отели, рейсы, поезда, трансферы |
| `domains/trips/inspire.py` | Подбор направлений под размытый запрос |
| `domains/trips/planner.py` | Варианты поездки, объяснения, компромиссы, состыковки |
| `domains/trips/rules.py` | Понимание реплик правилами |
| `domains/trips/arbiter.py` | Сверка ответа LLM с текстом и правилами |
| `domains/trips/domain.py` | Этапы диалога, пересборка плана, корзина, заказ |
| `core/` | Цикл агента, клиент LLM, извлечение с ремонтом JSON, защита от инъекций |
| `apps/web.py`, `apps/static/` | Веб-приложение |

## Разработка

```bash
make install   # .venv и зависимости
make test      # тесты без сети
make run       # приложение на http://localhost:8080 без Docker
make up        # docker compose up --build
make eval      # сценарии в режимах: правила, LLM, «плохая модель»
make simulate  # LLM играет путешественников (нужен ключ)
```
