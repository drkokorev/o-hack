# О!дин запрос — AI-агент поездки (трек «О!дин запрос»)

Пользователь описывает поездку обычными словами, а агент уточняет недостающие сведения, предлагает направления и собирает демонстрационные варианты. Есть полный сайт и встраиваемый чат. Цены, расписания, наличие и оформление — демонстрация: деньги не списываются, реальные брони и билеты не создаются.

- Видео-скринкаст: _добавим к сдаче_
- Развёрнутый сервис: _опционально_

## Общая версия и ветки

`main` содержит единую реализацию: маскирование личных данных, интерфейс и темы, редактирование/отмену сообщений, 3D-глобус, точный выбор мест и отелей, улучшения дат и диалога, GigaChat и локальную GigaAM. `artemiy` — рабочая ветка Артемия, `daniil` — Даниила. Перед работой обновляйте свою ветку из `main`, затем возвращайте проверенные изменения через pull request. Исходные версии объединённых веток сохранены метками `archive/2026-10-28/*`.

Под улучшениями ML здесь понимаются разбор реплик, промпты, правила, проверки и состояние диалога. Обучение новых весов модели не проводилось. [Состав, проверки и ограничения](docs/28_Единый_сайт.md).

## Быстрый старт

```bash
git clone --branch main git@github.com:ostrovok-hackathon-2026/iskusstvennyi-praim.git
cd iskusstvennyi-praim
cp .env.example .env
# В .env укажите GIGACHAT_AUTH_KEY или ODIN_SECRET_ENV_FILE с личным ключом.
# Разместите GigaAM в ../models/gigaam-v3-int8 или задайте ODIN_VOICE_MODEL_DIR.
docker compose up --build --wait
# открыть http://localhost:8080
```

Если исходники получены ZIP-архивом, распакуйте его и выполните те же шаги в распакованной папке. Ключ и веса модели в архив не входят. Для подготовки весов вне репозитория можно в отдельном окружении установить `requirements-voice.txt` и выполнить `python -m tools.setup_voice_model --output ../models/gigaam-v3-int8`; скрипт проверяет контрольные суммы.

Попробуйте: «В Сочи из Москвы с 5 по 12 декабря вдвоём» → на вопрос о составе ответьте «2 взрослых» → «беру 1 вариант» → «да, оформляй» → «оплата СБП» → «да, подтверждаю». Или опишите отдых без точных дат: агент уточнит их или предложит идеи без расчёта стоимости.

На полном сайте и во встроенном чате отдельный микрофон запускает и останавливает диктовку. После распознавания текст можно исправить и отправить стрелкой. Речь обрабатывает GigaAM на сервере приложения; при сбое внешнее распознавание браузера не включается. Лимит одной записи — 20 секунд. Внизу сайта и чата доступны `/terms` и `/privacy`: демонстрационные документы, не заменяющие настройку реквизитов оператора.

Большой глобус позволяет выбрать место и затем показывает маршрут. Короткое знакомство с сервисом можно пропустить или открыть снова. На телефоне доступны разделы «Чат», «Варианты» и «Глобус». В выбранной поездке раскрыты дорога туда и обратно, проживание и оба трансфера; тип трансфера меняется с пересчётом времени и суммы. [Изменения интерфейса и проверки](docs/29_Дизайн_и_состав_поездки.md).

По умолчанию используется GigaChat-2-Max и локальная GigaAM. GigaChat — облачный сервис: текущий текст и необходимые параметры поездки отправляются ему для разбора, а итог проверяется правилами приложения. Ключ нельзя включать в Git или передаваемый архив; в Docker личный файл подключается только для чтения, а не передаётся как переменная контейнера. Если ключ или папка GigaAM не заданы, стандартный запуск завершается с указанием проблемы; пока голосовая модель не загрузилась, `/health` не сообщает о готовности.

## Языковая модель и надёжность

Можно подключить другой OpenAI-совместимый API (`LLM_PROVIDER=openai`) или отдельно запущенный локальный совместимый сервер (`LLM_PROVIDER=local`, `LLM_BASE_URL`, `LLM_MODEL`). Для запуска Python-приложения только с правилами нужно явно задать `ODIN_MODE=rules`; этот режим понимает меньше формулировок. При временном сбое подключённой языковой модели приложение сообщает о переходе на правила. Личный бесплатный ключ GigaChat предназначен для личных тестов и не передаётся третьим лицам. Проверка подключения: `make llm-check`.

Пустые значения в `.env.example` означают документированные настройки по умолчанию. Для доступа жюри организаторы требуют отдельный разрешённый ключ и зашифрованный файл; [инструкция и проверка на вымышленных данных](docs/14_Ключи_для_жюри.md).

Пример подключения Cloud.ru при наличии разрешённого доступа:

```bash
cp .env.example .env
# в .env: LLM_PROVIDER=openai
#         LLM_API_KEY=<ключ сервисного аккаунта Cloud.ru>
#         LLM_MODEL=Qwen/Qwen3-235B-A22B-Instruct-2507  (или openai/gpt-oss-120b)
make llm-check      # связь, JSON-режим, задержка и понимание 8 фраз: LLM против правил
make simulate       # LLM играет 8 путешественников
```

Модель понимает реплику и может формулировать отдельные ответы о месте по фрагментам путеводителей — это RAG. Цены, рейсы, отели, ограничения и оформление рассчитывает код; критичные ответы и варианты выводятся без свободного пересказа модели. Путеводитель не подтверждает актуальные визы, погоду, расписания или тарифы. [План и карта возможностей](docs/30_План_модели_и_источников.md).

Свободный ответ проходит эвристическую проверку (`core/answer.py`); она не гарантирует фактическую точность или обнаружение всех выдуманных утверждений. Если проверка не прошла, показывается ответ приложения. Без ключа модели агент отвечает по правилам и может показывать фрагмент путеводителя с источником. Живой прогон с моделью: `make answers` (отчёт `eval/answers_report.md`).

Можно отдельно запросить «только перелёт»: агент уточнит маршрут, дату и направление билета и покажет демонстрационные рейсы без отеля. Бронирование отдельных билетов и реальные тарифы не подключены. Пакетные туры туроператоров также не подключены; агент сообщает об этом и может собрать самостоятельную демонстрационную поездку с отелем и дорогой. Демо-варианты не являются настоящими предложениями поставщиков.

В том же чате можно запросить только жильё или только трансфер, сравнить два отеля и составить две последовательные демонстрационные остановки. Для нескольких номеров агент просит явно распределить взрослых и детей; цены считаются по каждому номеру, но наличие и детские льготы не проверены. Реальные трансферы, туры, детские тарифы и покупка не подключены. [Архитектура и ограничения](docs/32_Архитектура_сервисов_и_критерии.md).

Понимание реплики сверяется с текстом и с правилами (`domains/trips/arbiter.py`):

- оформление и отмена — только по явному согласию, которое видят правила; «давай подумаем», «да нет», вопрос — не согласие; отмена брони в два шага;
- поле без опоры в тексте отбрасывается (модель выдумала «с собакой» или повторила «на два дня позже» из прошлой реплики);
- в датах, числах и действиях главнее правила;
- после трёх сбоев подряд модель 30 секунд не вызывается, агент идёт по правилам; отказ провайдера от `response_format` и ответ «в форме схемы» обрабатываются.

### Приватность демо

Перед обращением к модели сервис автоматически заменяет обнаруженные личные данные метками вида `[имя_1]`, `[телефон_1]` — одно значение в разговоре получает одну метку, так модель понимает связи в тексте, не видя самих данных. Таблица «метка → значение» хранится только в памяти сессии и никуда не передаётся; в ответ пользователю возвращаются лишь имена, номера документов и контакты не повторяются. Скрываются имена, контакты, номера документов, реквизиты и некоторые другие чувствительные сведения. Для имён используются локальная модель Natasha и дополнительные правила; распознавание выполняется на сервере приложения. Проверяются также сведения в контексте и повторных запросах. Если после маскирования остались определённые признаки чувствительной информации или фильтр не сработал, текст не отправляется модели: диалог продолжается по локальным правилам, которые могут понимать меньше формулировок. Старые свободные реплики в модель повторно не отправляются и в серверной истории поездки не хранятся.

Это **эвристический фильтр, а не гарантия обезличивания**: он может пропустить необычно записанные сведения, сведения о здоровье и другие личные подробности или ошибочно скрыть полезный текст. Для некоторых формулировок об аллергии сохраняется только требование к питанию; при более сложных запросах скрытие деталей может ухудшить ответ. Оставшиеся параметры поездки, даты и сочетания признаков также иногда позволяют определить человека. Слишком длинное сообщение отклоняется целиком, а не обрезается перед проверкой. Подробности и ограничения — в [отчёте о маскировании](docs/27_Маскирование_перед_моделью.md).

Состояние поездки хранится в памяти процесса до сброса или истечения времени неактивности (`SESSION_TTL_SECONDS`, по умолчанию час). Полный сайт сохраняет последние 60 сообщений, черновик и ссылку на сессию в `sessionStorage` этой вкладки; обновление страницы получает текущее состояние сервера без повторной отправки сообщений или оформления. Локальная запись устаревает через час, закрытие вкладки, сброс или перезапуск сервера могут завершить сессию. Встраиваемый виджет использует тот же чат и восстановление. Идентификатор сессии — секрет доступа к ней, полноценной авторизации в демо нет. Приложение само не пишет текст чата или аудио в обычные логи, но это не гарантирует настройки журналов прокси, хостинга, браузера и поставщика модели. Внешнее браузерное распознавание отключено. Подробнее об ограничениях и проверке 152-ФЗ — в [отчёте по диалогу и данным](docs/24_Диалог_и_персональные_данные.md).

## Качество

`make test` запускает автономные тесты диалога, дат, состояния, приватности, каталога, карты данных и демонстрационного оформления. Контракт поиска Островка проверяется на имитации ответов и не создаёт сетевых бронирований. `make eval` и `make simulate` содержат дополнительные сценарии; для проверки с языковой моделью нужен настроенный провайдер. Результаты отдельных экспериментов не гарантируют качество на произвольных запросах.

Последние исправления диалога и **открытые ошибки**, найденные в 90 сценариях с GigaChat, описаны в [передаче изменений и проверок](docs/27_Передача_диалог_и_проверки.md). Там же находятся сценарии, результаты и инструкции повторения.

Командные материалы: [реестр требований и сроков](docs/08_Единый_реестр.md), [матрица требований](docs/15_Матрица_требований.md), [реестр проверок](docs/10_Реестр_проверок.md), задачи [для ML](docs/12_Передача_ML_и_диалога.md) и [для фронтенда](docs/13_Передача_фронтенд_и_дизайн.md).

Состав объединённой версии и результаты интеграционных проверок — в [отчёте](docs/25_Объединение_диалога_и_дизайна.md); настройка моделей и результаты их проверки — в [отчёте о запуске моделей](docs/26_Модели_по_умолчанию.md).

## Данные

У команды пока нет доступа к партнёрскому API Островка. Мы используем открытые датасеты и явно помечаем модельные данные:

- **Объекты размещения — записи из открытой карты.** 65 924 записи из [Overture Maps Places](https://docs.overturemaps.org/attribution/), релиз 2026-10-21.0: название и координаты, иногда адрес и сайт. Это не подтверждение актуальной работы объекта или доступности номера. Шесть городов добавлены 27.10.2026: Ярославль, Екатеринбург, Самара, Уфа, Пермь и Тюмень (817 записей, до 300 на город). Основные 34 направления содержат все объекты, прошедшие фильтры; остальные — ограниченную выборку. Расстояние до моря считается по пляжам Overture, до аэропорта — по координатам OurAirports, по прямой. Происхождение и ограничения подробно описаны в [обзоре источников](docs/18_Источники_и_сервисы.md). Базовый каталог собирает `python -m tools.build_hotels`, шесть новых городов — `python -m tools.expand_cities_20261027` (нужны DuckDB и сеть).
- **Поиск и выбор отеля.** После выбора направления можно написать «покажи реальные отели» или «найди отель Campanile Taverny». Показанную запись можно выбрать номером, точным названием или кнопкой; выбранный идентификатор сохраняется при изменении дороги. Данные снимка не содержат подтверждённых цен и доступности. Последующие расчёты маршрутов и цен остаются демонстрационными; если выбранную запись невозможно связать с таким расчётом, приложение не подставляет другой объект молча.
- **Цены, рейтинги, отзывы, питание и условия отмены отелей — модельные.** Их нет в используемых открытых данных. Примеры отзывов и жалоб сгенерированы для демонстрации и не описывают реальный опыт гостей; карточки помечены как демо.
- **Климат — исторические данные.** Средние по месяцам за 2022–2025 годы из [Open-Meteo](https://open-meteo.com) (CC BY 4.0): температура днём и ночью, дождливые дни, температура моря. Это не прогноз погоды на конкретную поездку. Для шести добавленных городов данные загружены 27.10.2026. Бесплатный онлайн API имеет [отдельные условия](https://open-meteo.com/en/terms), в том числе ограничение некоммерческим использованием. Файл `domains/trips/data/climate.json`, пересборка — `python -m tools.build_climate`.
- **Фото направлений — реальные**, из Wikimedia Commons со свободными лицензиями: главное фото и галерея из лучших снимков (категории Featured pictures и Quality images). Автор и лицензия подписаны на каждом снимке (`tools/build_images.py`, `apps/static/img/credits.json`). Фото отелей — иллюстрации по типу отеля, так и подписаны.
- **Глобус и каталог карты.** Снимок содержит 283 561 запись: 161 662 географические, 65 924 размещения для 75 групп направлений, 48 101 аэродром, 7 866 координат пляжей и 8 кемпингов. На глобусе размещены восемь стилизованных моделей известных объектов, 108 объектов Всемирного наследия ЮНЕСКО и 110 вручную отобранных событий. Для наследия и видов событий используются условные модели категорий; все модели увеличены для наглядности, их основание привязано к координате источника. Координаты большинства событий обозначают город, а не площадку; исключение отмечается в карточке. При наложении объекты остаются в списке карты, группы привязаны к одной из входящих точек, а не к среднему положению. Даты событий проверены на 28.10.2026 и автоматически не обновляются. Источники и оговорки — в карточках и [THIRD_PARTY.md](THIRD_PARTY.md). В демо-планировщике доступны 75 групп направлений; точки карты сами по себе не становятся вариантами бронирования. Цены и наличие не следуют из снимка.
- **Страна, город и валюта.** Автоматическая подсказка города по публичному IP сохранена. В поставку входит компактный индекс DB-IP City Lite для поддерживаемых городов отправления; дополнительных настроек для него не нужно. В интерфейсе показывается только город, его можно изменить. Внешний сервис геолокации не вызывается. Индекс не покрывает все адреса; localhost, VPN и неподдерживаемый город могут не дать подсказку. Можно задать собственную локальную MMDB через `ODIN_CITY_DATABASE`. Каталог содержит 290 городов отправления. Валюты RUB/EUR/USD пересчитывают модельные рублёвые суммы по сохранённому курсу; бюджет в диалоге — в рублях.
- **Голос и избранное.** Отдельный микрофон запускает и останавливает диктовку; во время записи видна одна кнопка остановки и таймер. После распознавания текст проверяется перед отправкой. Используется GigaAM на сервере приложения, внешнего браузерного распознавания нет. Избранные и скрытые варианты сохраняются в браузере и учитываются в следующем подборе с сохранением обязательных условий поездки.
- **Атмосфера и звуки.** Пять тем: море, снежные горы, город, лес и закат. Короткие звуки создаются в браузере после явного включения кнопкой в шапке; по умолчанию выключены. Выбор сохраняется, во время диктовки и при скрытой вкладке звуки приглушаются. Аудио с сервера не загружается.
- **Сводка и история.** В сводке отображаются только условия, которые вернул сервер. Их можно изменить нажатием на плашку или через меню. Доступны редактирование последней реплики и отмена одного последнего шага подбора с восстановлением серверных условий. Оформление заказа не откатывается. Новая поездка запускается через меню чата с подтверждением.
- **Встраиваемый чат.** На странице сервиса разместите `<script src="http://localhost:8080/static/embed.js" defer></script>`, заменив адрес на адрес развёрнутого приложения. Откроется компактный чат с тем же сервером и логикой, что у полного интерфейса. Виджет не считывает содержимое страницы, на которую его вставили. Для публичного развёртывания используйте HTTPS и проверьте политику безопасности сайта.
- **География и интеграция.** Поиск географических названий использует 161 662 записи GeoNames; это не каталог предложений. Реальные доступность, тарифы и бронирование не подключены. [Схема возможной интеграции с Островком](docs/03_ostrovok_integration.md) отдельно показывает готовые и будущие шаги; read-only адаптер поиска проверен только на имитации ответов API.
- **Демо-предложения.** Каталог сценариев охватывает 75 направлений и 7 городов отправления. Реальное наличие рейсов, их маршруты и визовые требования не проверяются; эти сведения нужно получать у поставщиков и проверять отдельно.
- **Рейсы, поезда, трансферы и их цены — модельные (синтетика).** Генерируются детерминированно: время в пути считается по реальному расстоянию, цены зависят от сезона, перевозчики вымышленные («Авиа Альфа»). Оплата имитируется.

Для перехода на настоящий источник потребуется связать поиск с актуальными тарифами и проверкой брони; готовый read-only адаптер пока не является заменой демо-планировщика. Дальнейшие шаги и границы интеграции описаны в [схеме](docs/03_ostrovok_integration.md).

В Docker пространственный индекс собирается из исходных снимков при сборке образа. Для локального запуска выполните `python -m tools.build_map_catalog`; созданный индекс не добавляется в Git. Границы карты описаны в [передаче фронтенда](docs/20_Передача_фронтенд_глобус.md).

## Маршруты

- `/` — веб-интерфейс с картой, чатом, вариантами и демонстрационным оформлением
- `/static/widget-demo.html` — пример встраиваемого чата на странице другого сайта
- `/health` — `{"status": "ok"}`, когда сервис и обязательная локальная модель голоса готовы; доступность облачной модели подтверждается отдельным запросом к ней
- `GET /api/map/catalog`, `/api/map/clusters`, `/api/map/points`, `/api/map/point/{id}` — открытый снимок и пространственная выдача
- `GET /api/visitor-country` — приблизительная страна по адресу соединения, без возврата адреса
- `GET /api/visitor-city` — приблизительный город по локальной MMDB-базе, если она подключена; без возврата IP и внешних запросов. Без базы подсказка пустая.
- `POST /api/chat` — `{"text": "...", "session_id": "..."}` → ответ агента, этап, понятые параметры и данные для карточек
- `GET /api/info`, `POST /api/reset`, `/api/docs` — описание API

Тестовые учётные данные не нужны.

## Как устроено

Управляемый агент: LLM извлекает из реплики пожелания и действия в Pydantic-схему, а решения принимает код — какой вопрос задать, какие направления предложить и когда показать демонстрационное оформление. Правила уменьшают число неподтверждённых предположений, но не гарантируют отсутствие ошибок. Отели и цены в демонстрационных вариантах не являются проверенными предложениями.

```
реплика → защита от инъекций → понимание (LLM, правила дополняют и страхуют)
        → слияние с состоянием поездки → решение этапа:
          нет направления  → идеи без выдуманных дат и цен, либо подбор при достаточных данных
          нет параметров   → уточняющий вопрос; если человек не знает, не повторять его бесконечно
          всё есть         → 3 варианта: оптимальный / экономный / комфорт + проверка состыковок
          выбор            → корзина → выбор демо-оплаты → отдельное подтверждение → условный заказ
        → изменения («на два дня позже», «дешевле», «с собакой») пересобирают план и показывают, что изменилось
```

| Путь | Назначение |
| :--- | :--- |
| `domains/trips/geo.py`, `domains/trips/data/geo.json` | Проверка и загрузка справочника направлений, городов вылета и пересадок; расчёт расстояний |
| `domains/trips/climate.py` | Климат по месяцам (Open-Meteo) |
| `domains/trips/offers.py` | Отели (настоящие объекты + модельные цены), рейсы, поезда, трансферы |
| `domains/trips/inspire.py` | Подбор направлений под размытый запрос |
| `domains/trips/dialogue.py`, `tent.py` | Уточнения и идеи без цены; отдельный сценарий со своей палаткой |
| `domains/trips/world_places.py`, `providers/ostrovok.py` | Географический справочник и изолированная заготовка поиска по API Островка |
| `domains/trips/planner.py` | Варианты поездки, объяснения, компромиссы, состыковки |
| `domains/trips/rules.py` | Понимание реплик правилами |
| `domains/trips/arbiter.py` | Сверка ответа LLM с текстом и правилами |
| `domains/trips/domain.py` | Этапы диалога, пересборка плана, корзина, заказ |
| `core/` | Цикл агента, клиент LLM, извлечение с ремонтом JSON, защита от инъекций |
| `apps/web.py` | HTTP API и хранение сессий в памяти |
| `apps/static/index.html`, `app.css`, `app.js` | Разметка, стили и поведение полного сайта |
| `apps/static/trip-map.js`, `trip-map.css` | Самостоятельная карта: каталог направлений, GeoJSON и обработчик выбора передаются извне |
| `apps/static/widget.html`, `widget.css`, `widget.js`, `embed.js` | Встраиваемый чат и его подключение к странице |

Карту можно использовать отдельно от чата: подключить `trip-map.css` и `trip-map.js`, создать компонент через `createTripMap({container, onChoose, apiBase})`, передать `setData({places}, geojson)` и вызвать `draw({origin, targets})`. Для глобуса нужны статические ресурсы и API карты; `apiBase` по умолчанию совпадает с источником скрипта. Список `places` и `geojson` используются для списка быстрых направлений и запасной карты, если пространственный API или WebGL недоступны. `onChoose` передаёт выбранную страну, город, событие, достопримечательность или отель. Основное приложение повторно проверяет код страны и идентификаторы города и отеля на сервере; постороннему приложению необходимо сделать такую же проверку. Выбор отеля не подтверждает наличие и не создаёт бронь.

## Разработка

```bash
make install   # .venv и зависимости
make test      # тесты без сети
make run       # приложение на http://localhost:8080 без Docker
make up        # docker compose up --build
make eval      # набор диалоговых сценариев без сети, eval/guided_report.json
make simulate  # LLM играет путешественников (нужен ключ)
```
