# Передача для чата с дизайном: карта и реальные данные

Изменения находятся в ветке `codex/ml-dialogue-evaluation-20261027`, ответвлённой от `codex/fix-stay-dates-20261027`. Файлы карты интерфейса не менялись, но `app.js`, разметка чата и файлы виджета изменены функционально: подсказки берутся из ответа сервера; голос вызывается удержанием кнопки отправки. Перед объединением сохранить оба изменения и проверить их в новом дизайне, не перезаписывая параллельную ветку.

## Источники и смысл точек

Серверный каталог объединяет 65 924 записи объектов размещения, 48 101 аэродром, 161 662 географических записи, 7 866 округлённых координат пляжей и 8 точек категории campground. Все точки — из локальных открытых снимков; [происхождение и ограничения](18_Источники_и_сервисы.md). Это **все записи в нашем сохранённом каталоге**, не все объекты мира и не подтверждённая доступность.

Географический справочник шире гостиничного: объекты размещения загружены вокруг 75 групп направлений, а не для каждого из 161 662 географических объектов. Выбор другого города не создаёт для него недостающие отели. Записи размещения можно показывать по границам карты или группам направлений; точная принадлежность каждого отеля конкретному городу не установлена.

У отеля карта может показать имя, координаты, иногда адрес/сайт и источник. Цена, звёзды, рейтинг, отзывы, удобства, наличие, поезд/рейс и трансфер в текущем планировщике остаются демонстрационными; их нельзя подписывать как факты источника. Для campground данные не подтверждают места под собственную палатку или разрешение огня. Фотографии отелей текущего интерфейса — иллюстрации, а не фотографии конкретных объектов.

## Контракт API

Базовый URL — тот же, что и у `/api/chat`; новых ключей для карты не требуется.

1. `GET /api/map/catalog` возвращает `catalog_version`, `counts`, `sources` и общее предупреждение. У каждого источника указаны ссылка, лицензия, версия и дата получения, если она известна. `counts.hotel` сейчас 65 924; возможные значения вида `kind`: `hotel`, `camping`, `airport`, `beach`, `city`, `all`.
   `GET /api/map/countries` отдаёт 250 географических групп: 249 кодов из исходного справочника и используемый источниками дополнительный код `XK` для Косово (не ISO 3166). Для групп указаны числа записей городов, аэропортов и наших направлений. `GET /api/map/destinations` отдаёт 75 направлений с кодом страны, координатами и количеством записей размещения и кемпингов в каждой группе. Число объектов размещения в стране здесь получается **по стране направления**; страна каждой исходной записи отдельно не проверена.
2. Для обзора без отрисовки десятков тысяч маркеров используйте `GET /api/map/clusters?kind=hotel&zoom=3&west=-180&south=-90&east=180&north=90`. `zoom` 0–8; каждый элемент `items` имеет `id`, `count`, `lat`, `lon`. Сумма `count` включает все точки выбранного типа внутри указанных границ, без скрытого лимита. Сетка — простая географическая, не привязана к конкретной библиотеке карты.
3. Для видимой области используйте `GET /api/map/points?kind=hotel&west=39&south=43&east=40&north=44&limit=1000`. В ответе `items` и `next_cursor`. Дополнительные фильтры: `country_code=RU` для страны/территории и `destination_id=yaroslavl` для группы направления; те же фильтры принимает `/api/map/clusters`. Например, `kind=city&country_code=RU` или `kind=hotel&destination_id=yaroslavl`. У пляжей нет проверенного кода страны, поэтому при фильтрации по стране они не включаются; используйте границы карты. Гостиницы по стране фильтруются по группе направления, а не по проверенной границе каждого объекта. Продолжайте запросы с теми же фильтрами и `cursor=<next_cursor>`, пока он не станет `null`; лимит страницы 1–1000. На каждом изменении границ/вида или `catalog_version` начинать с `cursor=0`; старые ответы отменять или игнорировать.
4. Каждая точка содержит стабильный в пределах версии каталога `id`, `kind`, `name`, `lat`, `lon`, `source`, `source_id`, `id_quality`, `subtype`, `address`, `website`, `country_name`, `country_code`, `code`, `confidence`, `destination_id` и `extra`. Часть полей `null`. `source_id` с `id_quality=partial` у старых отелей — сокращённый ID; у пляжа он отсутствует, а координата округлена. Не склеивать записи только по одинаковому названию и не считать разные ID гарантией разных физических отелей.
   Чтобы открыть отдельно любую выбранную запись, используйте `GET /api/map/point/{id}` (URL-кодируйте ID); ответ включает данные точки и сведения об источнике, отсутствующая запись даёт 404. Это позволяет сделать карточку каждой записи каталога и ссылаться на неё без повторного перебора страниц.
5. Область через 180-й меридиан задаётся `west > east`; недопустимые координаты, виды и размеры страниц дают 422. Если индекс отсутствует, сервер возвращает 503. В Docker он автоматически строится из входных файлов при сборке; локально вне Docker — `python -m tools.build_map_catalog`.

Для ссылки источника используйте объект `sources[item.source]` из каталога; внешний `website` не проверен, поэтому открывайте только безопасные `https/http` адреса. Поля имён и адресов отображайте как текст, не как HTML. Не показывайте все 283 561 маркеров одновременно: обзорные кластеры + страницы для видимой области позволяют учесть каждую запись и сохранить отзывчивость интерфейса.

Ответ `/api/chat` дополняется массивом `suggestions`: он соответствует текущему вопросу или результату. При отсутствии поля старый интерфейс может использовать собственный запасной вариант. Новый ответ на фразу «покажи реальные отели» — текст из открытого снимка без цен и условий; вопрос об адресе выбранного отеля отвечает по записи источника либо сообщает, что адрес не указан. Уточнение «покажи все точки мира» не гарантирует полный каталог мира: сервер отдаёт только собранные исходные данные.

Голос: сохранить общий `voice-input.js` и подключение в основном чате и виджете, удержание кнопки отправки, отображение распознанного текста до отдельной отправки, статус и предупреждение о способе обработки. `GET /api/voice` сообщает режим; локальный GigaAM при отдельной настройке принимает WAV через `/api/voice/transcribe`, иначе используется поддерживаемое браузером распознавание. Подробности и ограничения — в [разборе](23_Открытые_решения_и_голос.md). Реальный микрофон и соединение с новой дизайн-веткой ещё нужно проверить.
