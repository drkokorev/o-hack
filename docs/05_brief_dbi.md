# Продуктовый бриф: голосовой ассистент клиники (кейс DBI)

> Черновик к КТ1 (15 октября). После получения данных DBI уточнить цифры и ограничения.

## Проблема
Пациенты записываются к врачу по телефону через регистратуру. В пиковые часы линия занята, звонки теряются, оператор тратит время на однотипные операции: запись, перенос, «на когда я записан», «когда принимает врач». Вечером и в выходные записаться голосом невозможно. Клиника теряет пациентов, которые не дозвонились.

## Целевая аудитория
- **Пациенты**, которым удобнее позвонить, чем пользоваться приложением, — в первую очередь люди старшего возраста и родители, записывающие детей.
- **Клиника**: руководитель регистратуры и колл-центра, которому нужно снизить нагрузку на операторов и не терять звонки.

## Ценностное предложение
Пациент звонит и решает вопрос записи голосом за 1–2 минуты, в любое время, без ожидания на линии. Операторы занимаются только сложными случаями.

## Решение
Голосовой ассистент на открытых LLM (Cloud.ru) и детерминированной бизнес-логике:
1. **Понимание запроса.** Определяет цель (запись, расписание, статус, перенос, отмена), врача или специальность, дату и время. Жалобы направляет к специалисту, диагнозов не ставит.
2. **Подбор врача и времени.** Предлагает до трёх ближайших слотов. Если в желаемое время мест нет, сам предлагает альтернативу и объясняет её.
3. **Запись, перенос, отмена.** Только после явного выбора или подтверждения пациента. Номер записи называется голосом.
4. **Статус и расписание.** Отвечает по актуальным данным расписания.

Архитектура: LLM только разбирает фразу. Слоты, записи и тексты ответов формирует код, поэтому ассистент не может выдумать время приёма. Если LLM недоступна, работает разбор по правилам.

## Метрики успеха

| Метрика | Цель для MVP | Как меряем |
| :--- | :--- | :--- |
| Доля диалогов, завершённых без оператора (запись, перенос, статус) | ≥ 80% на тестовых сценариях | Прогон набора сценариев |
| Точность разбора фразы (цель, специалист, дата, время) | ≥ 90% по полям | Eval-набор из ~60 фраз с эталоном |
| Среднее число реплик до записи | ≤ 4 | Логи диалогов |
| Задержка ответа (без синтеза речи) | ≤ 1,5 с с LLM; < 50 мс на правилах | Замер в API (`latency_ms`) |
| Записей с ошибкой (не тот врач или время) | 0 | Проверка подтверждений против расписания |

Бизнес-эффект для клиники: ❓ уточнить у DBI долю типовых звонков и стоимость минуты оператора.

## Ограничения
- Ассистент не ставит диагнозы и не даёт медицинских рекомендаций, только направляет к специалисту.
- Срочные состояния (боль в груди, затруднённое дыхание) должны переводиться на оператора или в 103. Это пока не реализовано, в планах.
- Идентификация пациента по имени или номеру записи; в проде — по номеру телефона звонящего.
- Персональные данные (152-ФЗ): в демо данные вымышленные; в проде хранение в контуре клиники.
- MVP работает с одним расписанием клиники. Интеграция с МИС DBI — через адаптер.

## Ключевой сценарий (прототип интерфейса)
`apps/web`. Пациент нажимает микрофон или пишет:
1. «Запишите к терапевту на среду после обеда».
2. Ассистент называет три варианта.
3. Пациент говорит «второй» и называет имя.
4. Ассистент называет номер записи, и запись сразу появляется в панели регистратуры.

То же доступно для расписания, статуса, переноса и отмены.
