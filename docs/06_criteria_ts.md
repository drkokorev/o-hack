# 06. Критерии оценки «Точки сборки» и где мы сейчас

Источник: Положение о хакатоне, Приложение № 1 (на producthack.ru, раздел «Положение о хакатоне»), прочитано 10 октября.
Оценки ставят эксперты, не меньше трёх на работу. Мультиагентная LLM-система только готовит черновик оценки и обратную связь.
Оценивается то, что реально показано: «использование конкретной технологии или LLM само по себе баллов не даёт».

## Отбор в финал — 23 октября, 5 критериев по 0–5, максимум 25

В финал проходят не больше 10 команд с кейса. При равенстве баллов выигрывает тот, у кого выше «Работоспособность», затем «Соответствие задаче».

| Критерий | Что нужно для 5 баллов | Что уже есть | Что доделать на хакатоне |
| :--- | :--- | :--- | :--- |
| **Соответствие задаче кейса** | Задача решена полностью, все ключевые требования кейса соблюдены | Все 6 функций из описания на сайте плюс отмена | Сверить с полным кейсом DBI 13.10; закрыть обязательные требования, которых нет на сайте |
| **Работоспособность** (первая при равенстве) | Стабильно работает от начала до конца | Сквозные сценарии, 66 тестов, fallback при сбое LLM, Docker | Развернуть на Cloud.ru; прогон на данных DBI; проверка голосом в живом браузере; нагрузка и долгие сессии |
| **Качество результата** | Результат корректен, обоснован и **воспроизводим** | Ответы формирует код, а не LLM, поэтому нет выдуманных слотов | **Eval-набор и цифры**: точность разбора фраз, доля успешных диалогов, ошибки распознавания; скрипт, который воспроизводит замер |
| **Техническая реализация и архитектура** | Компоненты связаны, обработаны ошибки, предусмотрено развитие | Слои ядро / домен / интерфейс, адаптер данных, fallback, ADR | Схема архитектуры и структуры данных под данные DBI; логирование; таймауты и обработка ошибок голоса |
| **Понятность использования** | Сценарий интуитивен, результат легко получить и понять | Подсказки-сценарии, панель регистратуры, повтор вариантов, подтверждения | Повтор записи перед подтверждением, понятные ответы «не расслышал», проверка UX на людях, не знакомых с проектом |

## Финал — 31 октября, 3 критерия по 0–5, максимум 15

При равенстве баллов порядок такой: ценность, затем реалистичность, затем питч.

| Критерий | Что нужно для 5 баллов | Что готовим |
| :--- | :--- | :--- |
| **Продуктовая ценность** | Эффект убедительно показан и связан с задачей | Цифры DBI: доля типовых звонков, нагрузка на операторов, пропущенные звонки; расчёт экономии; метрики из eval |
| **Реалистичность внедрения и развития** | Реалистичный план внедрения, ограничения учтены | Интеграция с МИС через адаптер, телефония, 152-ФЗ, контур клиники, стоимость инференса, дорожная карта |
| **Питч и ответы на вопросы** | Ясно объясняет проблему, решение, результат; уверенные ответы | Питч до 7 минут, живое демо и запасное видео; репетиции; каждый в команде понимает код |

## Что сдавать вместе с финальным артефактом (п. 5.5.4)

Без этих материалов решение **к финальной оценке не допускается**:
- [x] исходный код;
- [x] перечень библиотек и внешних сервисов с лицензиями — `THIRD_PARTY.md`;
- [x] файлы конфигурации — `.env.example`, `Dockerfile`, `requirements*.txt`;
- [x] инструкции по сборке и развёртыванию — `README.md`; дополнить разделом про развёртывание на Cloud.ru;
- [ ] описание архитектуры **и структуры данных** — `docs/02_architecture.md`; дополнить структурой данных DBI;
- [ ] прочие материалы для воспроизведения: eval-набор и скрипт замера.
