# Итоговый интерфейс: глобус, события и два одинаковых чата

Основа — `6693512c4a6dba729084f57032ee568af529b303`, ветка публикации — `artemiy`. Работа продолжена в версии Артемия. Размещение сводки из отчёта 38 заменено решением ниже. Изменения модели `f549225`, ПД `be4b2be` и все 32 миниатюры сохранены.

## Роли элементов

| Элемент | Итоговое поведение |
|---|---|
| Заголовок и этапы | Над глобусом: короткий заголовок текущего этапа, синий активный шаг, зелёный акцент. Этапы показывают ход работы, не открывают ещё одну форму маршрута. |
| Условия поездки | Над перепиской: выбранные маршрут, даты, состав и бюджет. Раскрываются по нажатию; значения редактируются отдельно. Пустых «откуда? куда? когда?» в сводке нет. |
| Начальные желания | Один набор в чате. После запроса остаются только подходящие к текущему вопросу ответы. Убран навязчивый пример «на два дня позже» в ответе с вариантами. |
| Глобус | Два прежних объёмных режима. Размер зависит от свободного пространства; автоматическое уменьшение до 280 px при выборе отеля снято. Новый маршрут сначала показывается на целой планете. Приближение открывает карту; изменение бюджета не сбрасывает камеру. |
| События | Три фотокарточки «Поводы поехать» доступны сразу, без поиска в фильтре. На карте сохраняется группировка и раскрытие по масштабу. |
| Варианты и корзина | Единственная основная кнопка в ответе ведёт к результату. Повтор над картой убран. Отель, дорога туда/обратно и трансферы остаются частями одной корзины. |
| Документы и атрибуция | Один общий футер вне чата и карты, доступный на всех экранах и во втором чате. Источники и лицензии доступны через «О проекте и данных» и карточки. |
| Второй сайт | `static/widget.html` открывает тот же интерфейс `/?embed=1`: сводку, редактирование, валюты, флаг, избранное, голос, результаты и корзину. Отдельной копии компонентов нет; скрытый WebGL не создаётся. |

Автоматическое определение отправного города по локальной IP-базе сохранено. Из интерфейса убрана только пометка. Явное указание города имеет приоритет.

## Завершённая подборка событий

Из 110 прежних точек оставлены **29 событий** в городах, точно совпадающих с направлениями каталога. **81 точка** без такого соответствия снята с показа. Ближайший посторонний город не подставляется. Реестр с идентификаторами и причиной исключения: [event-curation-20261029.json](event-curation-20261029.json). Исходная подборка восстанавливается из базового коммита.

Каждая оставленная карточка содержит фотографию, дату, город, короткое описание, источник и рабочее действие «Хочу на событие». Все 29 действий проверены до получения вариантов полной поездки. Выбор события не придумывает даты проживания, сохраняет бюджет/состав/отправление; при несовпадении уже выбранных дат сообщает об этом.

Добавлены 10 лицензированных тематических обложек, суммарно **1 577 728 байт**. Формула-1 иллюстрируется гоночным автомобилем, концерт — музыкантами, кино — кинозалом и т. п. Надпись «Тематическое фото» не выдаёт архивный снимок за фотографию будущего события. Автор, лицензия, исходная страница и дата фотографии записаны в [credits.json](../apps/static/img/events/credits.json); получение файлов воспроизводится скриптом [fetch_event_photos.py](../tools/fetch_event_photos.py).

Например, автомобиль — [Charles Leclerc, Tuscan Grand Prix 2020](https://commons.wikimedia.org/wiki/File:Charles_Leclerc_2020_Tuscan_Grand_Prix_-_race_day.jpg), Eustace Bagge, CC BY-SA 4.0. Парк — [A Friday in Global Village](https://commons.wikimedia.org/wiki/File:A_Friday_in_Global_Village.jpg), HiralH0305, CC BY-SA 4.0. Это тематические фотографии, а не подтверждение программы или наличия билетов.

По умолчанию показаны ближайшие три месяца. Когда заданы даты, подборка автоматически учитывает их и выбранный город; пользователь может переключиться на весь календарь. Ручной выбор периода не сбрасывается при следующей реплике. Даты/источники исходного календаря сохранены со старой отметкой проверки 28.10.2026; повторная проверка программ всех организаторов в этой задаче не заявляется.

Счётчики разных наборов пересекаются и не являются числом уникальных требований. Браузерные сценарии используют реальный локальный API в режиме rules. Голосовые состояния проверены с синтетическими сэмплами и заглушкой транскрипции: пользовательский микрофон не записывался. Отдельный контроль модели и готовности GigaAM записан в реестре после возврата сервера в режим models.

На небольшом экране длинная карта/список прокручиваются. Планета в исходном обзоре целиком помещается в свою область; намеренное приближение пользователя остаётся доступным. На ширине 320 px сводка проверенного сценария занимала 97 px, переписке оставалось 189 px при высоте окна 740 px. Это измерения конкретной поездки, не гарантия фиксированной высоты любых названий.

Неудачные попытки не скрыты: первый общий прогон нашёл устаревший тест снятых с показа событий; первый браузерный проход — неприменяемый бюджет числом; проверка моделей — перекрытие кнопок масштаба метками. Исправлены данные ожиданий, нормализация числового ввода и приоритет/размещение управляющих кнопок. Дополнительно уточнены два теста под свёрнутую сводку и формат текущего значения бюджета. Финальные прогоны перечислены в [реестре проверок](evidence/final-experience-20261029/checks.json).
