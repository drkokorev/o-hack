### Как повторить автоматические проверки

На машине разработки с Python 3.11+ и установленными зависимостями `requirements-dev.txt`:

```bash
python -m pytest -q
python -m eval.compare_models --models rules --output /tmp/travel-rules-report.json
```

Для разрешённого GigaChat-доступа дополнительно указать переменные провайдера локально и использовать `--models GigaChat-2-Max`; результаты зависят от версии модели, сети и времени. Не размещать секреты в команде, отчёте или Git. Для запуска приложения по инструкции жюри использовать Docker Compose; это отдельная проверка от unit-тестов.

Следующие сценарии подготовлены командой и применялись при разработке. Поэтому 38/38 показывают отсутствие известных регрессий на этом наборе, а не точность в процентах на реальных пользователях. Проверка оценивает конечное состояние и отдельные признаки; она не полностью оценивает каждую промежуточную реплику, дизайн, безопасность или реальность данных.

## Учёт вопросов из Telegram

Принцип: **объявления организаторов > их ответы > пересказ встречи > сообщения участников**. Старые годы полезны для идей, но не являются правилами текущего года. Полноту истории нельзя обещать, пока Telegram не загрузил её целиком. Не сохранять в отчёт личные диалоги, имена участников, коды встреч и сырые выгрузки чатов.
