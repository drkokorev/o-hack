# 04. Журнал решений (ADR)

| # | Решение | Почему | Статус |
| :--- | :--- | :--- | :--- |
| 001 | Управляемый агент: LLM отвечает за понимание запроса, Python — за поиск, ранжирование и ответ | Демо не ломается, логику можно тестировать, работает на открытых моделях | Принято |
| 002 | Один OpenAI-совместимый клиент; провайдер задаётся через `LLM_BASE_URL` в `.env` | Cloud.ru, vLLM, Ollama и OpenRouter переключаются без изменения кода | Принято |
| 003 | Ответы детерминированные по шаблону, NLG-перефразирование включается флагом `LLM_NLG=1` | Нельзя выдумать цены, отели и причины выбора | Принято |
| 004 | Пустой поиск обрабатываем лестницей ослабления фильтров и явно говорим, что ослабили | Агент не отвечает «ничего не нашлось»; это заметно на демо | Принято |
| 006 | Состояние сессий храним в памяти процесса | Для демо достаточно; Redis только если понадобится несколько инстансов | Принято |
| 007 | Python 3.12, зависимости: pydantic, openai, python-dotenv | Минимум зависимостей | Принято |
| 009 | Всё созданное до 23 окт раскрываем как ранее созданные компоненты (`docs/07_preexisting.md`); дата зафиксирована коммитом `7bbf120` от 11 окт в удалённом репозитории | П. 7.3 правил: исключительные права на сданное решение переходят Островку. ❓ Это не юридическая консультация — при сомнениях уточнить у организаторов | Принято 10 окт |
| 010 | Правила работают всегда: дополняют пустые поля ответа LLM и заменяют её при сбое (`llm+rules`) | LLM пропускает части длинного запроса; без ключа демо всё равно отвечает. Правила консервативны: «без завтрака» не превращается в требование завтрака | Принято 22 окт |
| 011 | Параметры поиска (`HotelParams`) отделены от служебного состояния (`shown_prices`); в update добавлены `clear` и `cheaper` | LLM видит только то, что может менять; «бюджет не важен» и «а подешевле?» стали выразимы | Принято 22 окт |
| 012 | Каталог из файла через автоопределение колонок и явный `mapping` как запасной вариант | Формат данных Островка неизвестен до открытия; подключение должно занимать минуты | Принято 22 окт |
| 013 | Оценка на двух наборах: настроечном и отложенном, который не используется для подгонки правил | Набор, написанный вместе с правилами, завышает метрики. Правила 22 окт: 35/36 на настроечном, 7/20 на отложенном (полнота полей 100% и 69%) — основной путь понимания всё равно LLM | Принято 22 окт |
| 014 | В веб-демо понятые параметры показаны «билетом» с плашками, каждую можно убрать кликом без LLM | Объяснимость: пользователь видит, что агент понял, и исправляет это за один клик | Принято 22 окт |

Известные ограничения прототипа:
- Каталог отелей вымышленный; реальные данные появятся 23 октября.
- Пожелание «у моря» влияет только на ранжирование: отели без данных о расстоянии до моря не отсекаются.
- Правила ошибаются на незнакомых формулировках («на майские», «пяти тысяч», английский) — см. `eval/report_holdout.md`.
