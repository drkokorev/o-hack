# Документы демоверсии и приватность без изменения диалога

Дата: **29 октября 2026 года**. Исходник: `main` на коммите `28a7006de302dae00e88e55774fddd59727ee39e`. Изменения подготовлены в ветке `codex/privacy-voice-quality-20261029`.

Задача — добавить на localhost доступные документы и исправить лишние внешние маршруты данных, сохранив понимание запросов и ответы агента. По уточнению владельца документы остаются демонстрационной редакцией; реквизиты будущего оператора не выдумываются.

## Что изменено

- Внизу полного сайта появились ссылки на `/terms` и `/privacy`; такие ссылки добавлены и в виджет. Они открываются в новой вкладке, сохраняя разговор и набранный текст в исходной вкладке. Документы читаются без JavaScript и не вызывают модель.
- Условия описывают реальные возможности прототипа: подбор и имитированное оформление, демонстрационные предложения, отсутствие настоящих бронирований и списания денег. Политика объясняет текст, голос, обратимые метки, серверную сессию, настройки браузера и границы удаления.
- Реквизиты можно позже задать через `ODIN_OPERATOR_NAME`, `ODIN_OPERATOR_ADDRESS`, `ODIN_OPERATOR_EMAIL`. До их заполнения документ прямо сообщает о статусе деморедакции. Значения экранируются; неподходящий email не превращается в ссылку. Compose передаёт эти параметры приложению.
- Убраны обращения браузера и сервера к IPinfo. Необязательная локальная MMDB-база подключается через `ODIN_CITY_DATABASE`. Без неё город уточняется в диалоге; остаётся существующая кнопка геолокации с разрешением браузера и подтверждением города. Явный город в запросе и его последующее исправление сохраняют приоритет. Страна продолжает определяться по существующей локальной базе.
- Голос распознаётся GigaAM на сервере приложения. Неудача `/api/voice`, отсутствие или неготовность модели не включают внешнее браузерное распознавание. Текстовый ввод остаётся доступным. Перед первым включением объяснение есть и на полном сайте, и в виджете.
- Отмена, Escape, уход со страницы и скрытие вкладки останавливают захват и отменяют незавершённую отправку. Обычная остановка оставляет текст для проверки; нажатие «Отправить» во время записи сохраняет прежний путь отправки после распознавания.
- Исправлены две проблемы загрузки смыслового поиска: `tokenizers==0.23.3` добавлен в используемый Docker-сборкой `requirements.lock`; файл токенизатора и части модели защищены в `.gitattributes` от преобразования переводов строк. Содержимое модели в Git не заменялось, проверка контрольных сумм сохранена.

## Что сохранено для качества ответов

Исходники в `core/` и `domains/` не изменены относительно исходного коммита: модель, её инструкции, извлечение пожеланий, контекст, правила подбора, генерация ответов и действующее маскирование сохранены. Дополнительных ограничений на свободный текст и дополнительных согласий перед каждой репликой не введено.

На фиксированном наборе `final_holdout` все **16 реплик** дали те же ответы, виды результата, способ разбора и замечания проверки. Результат остался **7/8**. Сохранилось исходное расхождение `F05_new_search`: сценарий ожидает сохранение Москвы после новой поездки, текущий код её сбрасывает. Равенство результатов сохраняет и эту ошибку; оно не является оценкой качества на всех запросах или доказательством одинаковой генерации облачной модели.

В браузере дополнительно пройден настоящий диалог с настроенным GigaChat: полный запрос из Казани в Стамбул и последующее изменение транспорта. Оба ответа отмечены `llm+rules`; чтение документов не меняет идентификатор сессии, направление и город отправления.

Изменение удобства: автоматическая подсказка города по стороннему IP-сервису удалена. Без собственной базы город нужно назвать или подтвердить через существующую кнопку геолокации. Сторонние сервисы IP-геолокации автоматически не вызываются. Это может добавить уточнение для запроса без города; явно указанные условия обрабатываются прежним образом.

## Почему потребовалось исправление файла смыслового поиска

На Windows `core.autocrlf=true` преобразовывал файл токенизатора при получении исходников. Проверка показала:

- части ONNX-модели соответствуют исходной контрольной сумме;
- версия токенизатора в Git также соответствует сумме из `manifest.json`;
- рабочая копия получила **1 000 172** дополнительных байта CRLF и перестала соответствовать сумме;
- после сохранения исходных байтов и правила `-text` файл снова проходит проверку, обе прежние проверки смыслового поиска проходят.

Проверка целостности не ослаблялась. Добавление библиотеки само по себе было недостаточно: первый повтор всё ещё выявлял повреждение байтов рабочей копии. Изменения защищают и следующую чистую копию на Windows.

## Повтор проверок

Окружение должно содержать зависимости из `requirements.txt` и `requirements-voice.txt`, а также `pytest` из `requirements-dev.txt`. Веса GigaAM и разрешённый доступ к модели настраиваются по README; для тестов используются подмены, личный ключ не требуется.

```text
python -m pytest -q
python -m eval.dialogue_20261027 --set final_holdout --output after.json
python -m eval.privacy_dialogue_compare_20261029 before.json after.json --output comparison.json

playwright-cli -s=privacy open http://localhost:8080
playwright-cli -s=privacy run-code --filename eval/browser_demo_privacy_20261029.js
playwright-cli -s=privacy run-code --filename eval/browser_voice_privacy_20261029.js
playwright-cli -s=privacy run-code --filename eval/browser_legal_layout_20261029.js
```

`before.json` получают тем же сценарием на исходном коммите. Сравнение исключает время выполнения, сохраняя текст, результат и ошибки. Сценарий `browser_demo_privacy_20261029.js` обращается к настоящему локальному чату и может вызывать настроенную языковую модель; остальные браузерные проверки используют подмены или только интерфейс.

Для точечных изменений использованы ui-ux-pro-max и Playwright. Поиск рекомендаций о разрешении микрофона не дал релевантного результата после уточнения; применены общие правила доступности и обратной связи: нативные ссылки и диалоги, видимый фокус, понятные подписи, отмена и проверка на нескольких ширинах. Новый визуальный стиль не вводился.

## Границы результата

Документы описывают текущий прототип и остаются деморедакцией. Не установлены фактический будущий оператор, размещение, договоры, уведомления и порядок обработки для публичного запуска. Их заполнение не автоматизировано и не подменено общей галочкой. Соглашение для физлиц GigaChat ограничивает загрузку ПД других людей и использование доступа; код и пользовательские документы эти условия не изменяют. [Соглашение поставщика](https://developers.sber.ru/docs/ru/policies/gigachat-agreement/individuals).

Условия прав на проект, окончательная сдача, видео и тег `submission` не изменялись этой правкой. В основной ветке ничего автоматически не объединялось. Локальное приложение демонстрирует проверенную ветку; для общей версии команды изменения передаются через pull request.
